# v2.0.0 정식 출시 준비 — 2026-11-07

현재 공개 v2.0.0은 prerelease다. 이 변경은 검색 결과의 중복 근거 처리를
수정하며, 정식 출시나 독립 품질 평가 통과를 의미하지 않는다.

## 수정한 검색 결함

Hindsight의 원문 사실과 통합 observation이 같은 내용을 반환할 때, 출처별
대표 ID가 다르면 동일 내용이 결과 제한을 중복 점유했다. 또한 여러 줄짜리
근거의 중복 여부를 줄 목록과 비교해 같은 본문을 반복해서 이어 붙였다.

현재 SQL에서 접근 가능한 모든 출처가 확인된 hit만 받아들인 뒤,
같은 bank의 정확히 동일한 전체 본문을 먼저 묶는다. 유효한 출처의 ID·revision을
모두 남기고 가장 높은 기존 순위 점수를 유지한다. 그다음 대표 기억별 본문을
합치고 결과 제한을 적용한다. 다른 bank, 조건·부정·구두점이 다른 본문은
동일 근거로 합치지 않는다. 삭제된 출처가 포함된 hit는 중복 합산에 참여하지 않는다.

판단 임계값, reranker floor, 모델, 저장 정책과 기존 사용자 데이터는 변경하지 않는다.
이 결함이 과거 독립 평가 실패의 원인이었다고 확정할 수는 없다.

PR #17은 CI 통과와 자동 코드 리뷰의 미해결 지적 없음을 확인한 뒤
`70d7d4a2017821f2307ba04879ec220e5c51b553`로 머지했다.

### 후속: 검색된 조각 밖의 조건·예외 보존

실제 고정 Hindsight와 배포본과 같은 해시의 E5·BGE ONNX를 새 격리
PostgreSQL 18.6/vector 0.8.7에 연결했다. 검색 전 문서를 고정하고 admission은
scripted 확률 응답만 사용했다. Jev 키나 외부 판단 호출 없이 검색을 재현했다.
이 검증 환경의 전이 Python 의존성은 새로 설치했으며, 배포 bootstrap의 전체
의존성 closure와 같다는 주장은 아니다. Hindsight의 366개 Python 파일 tree와
모델 파일은 제품 런처의 고정 해시 검증을 통과했다.

실제 검색에서 앞부분의 `Atlas backup retention is 29 days.`만 회수하고,
뒤쪽의 `Records under legal hold must never be deleted, regardless of age.`를
빠뜨리는 회귀를 확인했다. 통합 검색이 현재 SQL에서 승인된 전체 본문을
반환하도록 수정했다. Native가 내놓은 조각은 출처 nomination과 순위에만
사용하며, 원문의 조건·예외를 지우거나 재작성하지 않는다. 별개의 출처가
검색되지 않은 문제까지 해결한 것으로 보고하지 않는다.

수정 전 scripted nomination 회귀 1건과 실제 Native 회귀 1건 모두 실패했고,
수정 후 관련 **11 passed** (14.54초)였다. 여기에는 기존 중복·출처 경계와
실제 Native 수정/삭제·같은 bank 병렬 저장의 회수가 포함된다.
세 앱의 동일 본문 저장 회귀는 SQL의 세 독립 turn ID가 모두 보존되고,
중복 제거된 검색 결과의 `sources`가 그 세 ID를 모두 인용하는지 확인한다.

PR #18의 자동 리뷰에서 서로 다른 Native 조각이 동일한 전체 원문으로
확장된 뒤 결과 제한을 중복 점유하는 경로를 추가로 발견했다. 해당 회귀를
먼저 실패로 재현하고, bank 안에서 확장된 승인 본문 집합을 한 번 더 묶어
출처 ID·revision을 합치도록 수정했다. 대표 ID는 가장 작은 원래 ID이며
가장 높은 기존 점수와 해당 본문 순서를 유지한다.

전체 본문 확장 응답은 client의 4 MiB 한도보다 작은 4,000,000 JSON byte로
제한한다. 넘치는 묶음은 조건·예외나 일부 출처를 잘라내지 않고 통째로
생략하며 뒤의 작은 결과를 계속 검토한다. `partial`·`omitted_due_to_budget`에
생략을 표시하고 MCP는 이를 "일치한 기억 없음"으로 설명하지 않는다.
byte budget 회귀 2건의 수정 전 실패도 확인했다.

예외 보존 수정 후 첫 전체 SDK 검증은 **262 passed, 2 failed, 1 skipped**
(219.74초)였다. 2개 실패는 기존 한국어 질의의 실제 신경 검색이며,
skip은 명시한 소유 synthetic 설치물이 필요한 configured plugin 소비다.
이 결과를 전체 통과로 보고하지 않는다. 이후 budget·리뷰 수정 도중의
전체 실행은 의도적으로 중단했으며 최종 검증으로 세지 않는다.

최종 제품 source `211b42e`에서 전체 SDK는 **266 passed, 2 failed, 1 skipped**
(185.28초)였다. 남은 두 실패와 skip은 위와 같고, 오류·추가 skip은 없다.
예외·budget·확장 후 중복·세 host 출처를 묶은 관련 검증은 **16 passed**
(18.90초)다. 새 SDK wheel의 15개 Python 파일은 실행 source와 byte-identical이며
wheel SHA-256은 `a92b9687917862a5ad7c9f120f15e7cb7477730f9c9ed62c3b72885050a20ab2`다.
기존 공개 source-free Core 두 wheel은 유지하고 새 SDK로 로컬 candidate를
재조립했다. candidate SHA-256은
`31c2a5c31c59b3f1a61e8da1eef154b7ceb6793c516d4bd99721a748a5a52e69`다.
공개 자산을 교체하거나 이 candidate를 정식 배포하지 않았다.
검증 집계·실패 이름·자산 지문은 [기계 판독 기록](2.0.0-search-verification.json)에 남긴다.

짧은 한국어 질의 `데이터베이스 저장 엔진 버전`은 여전히 실패한다.
후보는 찾지만 실제 BGE 점수 `0.02830672264099121`이 기존 `0.03` floor보다 낮다.
같은 문서의 영문 질문은 `0.9994109272956848`, 완전한 한국어 질문은
`0.5070528984069824`였다. tokenizer JSON과 AutoTokenizer의 input IDs·mask는
같았다. 이는 알려진 공개 개발 회귀의 진단이지 독립 품질 통과 근거가 아니다.
미리 고정한 중립 질문 포장 3종은 이 개발 사례에서 점수를 더 낮춰 채택하지
않았다. 제품의 floor·모델·질문 처리 코드는 바꾸지 않았다.

## 이번 검증

- 수정 전: 새 PostgreSQL 회귀 4건 중 중복 관련 2건 실패, 경계 2건 통과.
- 수정 후: 새 회귀 7건을 포함해 recall evidence / generation transport /
  authorization / collaboration / sync safety **73 passed, 5 skipped** (32.52초).
  건너뛴 항목은 실제 ONNX 자산과 호스트용 PostgreSQL 백업·복구 도구가 필요한 경로다.
- 실제 PostgreSQL 18.6, 격리된 새 임시 DB를 사용했다. 검색 nomination과
  admission은 scripted double이다. 실제 Hindsight 신경 검색이나 Jev 품질 검증이 아니다.
- 기존 Core processor / admission / content 회귀는 **198 passed** (0.47초).
  Core 제품 소스는 이번에 수정하지 않았다.
- 새 테스트 Ruff, 변경 Store의 구문·이름 오류 검사, 기존 공개 profile 검증과
  `git diff --check` 통과. 전체 제품 suite·새 shipping wheel 설치 검증은 미실행이다.

## 남은 정식 출시 조건

기존 독립 v43의 원본·실패 기록과 고정 기준은 유지한다.

| 지표 | 기존 관측 | 기존 출시 기준 |
|---|---|---|
| 정당한 명시 저장 | 70/80, Wilson 95% 하한 0.784972 | 하한 ≥ 0.95 |
| 이어가기 Hit@5 | 30/40, Wilson 95% 하한 0.598060 | 하한 ≥ 0.75 |
| 필수 근거 전체 회수 | 2/40 | 원래 평가 계약대로 별도 보고 |

이번 요청에서 추가 Jev 197회 호출은 승인됐다. 추가 공급자 호출은 0회이며
기존 ledger를 수정하거나 과거 cohort를 재채점하지 않았다. **검색 전용 평가에는
Jev 키가 필요 없다.** 현재 검색 엔진·모델·격리 DB는 준비했지만 새 독립 검색
corpus/gold와 기존 private 평가 자료는 연결되지 않았다. 전체 저장→검색 재평가에는
별도로 Jev 키와 호출 ledger가 필요하며 실행 전 197회 슬롯과 고정 입력을 확인한다.

이후 필요한 작업은 새 독립 196건·40질문 평가, 실제 세 앱의 startup/resume/compact
검증, 최종 source와 배포 wheel·설치 소비의 동일성 확인, 원래 CI의 실제 통과다.
Core CI의 과거 결제/지출 한도 실패는 해결됐다고 확인하지 않았다.
현재 release 자산·tag·prerelease 표시는 변경하지 않았다.
