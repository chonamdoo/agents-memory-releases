# v1.0.6 — macOS DB 자동 복구와 새 세션 기억 조회 지침

1.0.5의 macOS pgvector 패키지에 `vector.so`가 들어갔지만, 함께 배포한 PostgreSQL 18은 `DLSUFFIX=".dylib"`로 빌드돼 있었습니다. 이 때문에 `CREATE EXTENSION vector`가 실패하고 MCP만 연결된 상태에 머물렀습니다.

1.0.6은 신규 패키지에 `vector.dylib`를 넣습니다. 기존 설치에서는 1.0.5에서 배포한 모듈의 해시와 런타임 검증 기록을 확인한 뒤 올바른 파일 이름과 검증 기록을 자동 복구합니다. **DB 재생성, 키 재입력, 전체 재설치는 필요하지 않습니다.** 다른 파일이나 알 수 없는 모듈은 덮어쓰지 않습니다. 복구 도중 중단돼도 다음 실행에서 이어갈 수 있습니다.

OMP에서:

```sh
omp plugin upgrade agents-memory-local@agents-memory
```

업데이트 후 OMP에서 `/mcp reload`를 실행하고 `setup_status`의 **version: 1.0.6, ready: true**를 확인하세요. `~/.local/share/agents-memory-hindsight`를 삭제하지 마세요. 직접 설치 도우미로 등록한 사용자는 1.0.6 설치 스크립트를 같은 프로젝트·설치 경로로 다시 실행하면 기존 설정을 재사용합니다.

새 세션에서 저장된 기억을 확인하지 않고 답하는 문제도 보완했습니다. MCP 연결 지침과 조회 도구 설명에 첫 본격적인 답변 전 관련 기억 조회, 빈 검색 결과의 키워드 재확인, PR 작업의 리뷰어·담당자 규칙 확인을 추가했습니다. OMP 직접 등록에서 이 서버의 지침 전달이 꺼져 있던 설정도 보완합니다. 이는 호스트 모델에 전달하는 지침이며, 다른 도구의 실행이나 모든 모델 응답을 강제로 통제하는 기능은 아닙니다.

검증:

- 실제 PostgreSQL 아카이브의 `pg_config.h`를 읽는 패키지 검사에서 1.0.5의 macOS 오류를 재현하고 수정 아카이브 통과를 확인했습니다. 빌드 도구는 이제 두 플랫폼의 이 검사를 통과해야 연결기를 생성합니다.
- 실제 macOS 배포 아카이브 설치와 기존 1.0.5 파일 배치의 자동 복구를 검사했습니다. 복구 시 추가 다운로드·하위 프로세스 실행이 없고 키·설정·DB 표식의 바이트가 유지됐습니다.
- Linux PostgreSQL에서 새 DB의 `CREATE EXTENSION vector`, 벡터 거리 계산, 기존 기억 검색과 설정 보존을 확인했습니다.
- 새로운 Codex 6.1 Terra 세션에서 기억 검색을 명시하지 않은 일반 질문에 대해 실제 장기 기억 조회 후 답변하는 것을 확인했습니다. 실제 PR이나 리뷰 요청은 만들지 않았습니다.
- Python 81개, Go 8개 및 race 검사, 스타일·배포 계약 검사를 통과했습니다. GitHub Actions는 실행하지 않았습니다.

**이 수정본을 실제 Mac에서 실행한 검증은 아직 없습니다.** 파일 이름 계약과 아카이브·복구 검사는 Linux에서 수행했습니다. 새 세션 자동 조회의 실제 모델 검증도 같은 프로젝트의 Codex 한 사례이며 다른 호스트·모델 조합의 행동을 보장하지 않습니다. Apple Silicon macOS 15 이상 조건과 검색용 E5 임베딩 포함은 유지됩니다.
