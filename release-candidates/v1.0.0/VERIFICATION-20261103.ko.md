## 수명주기: 처음의 실패를 지우지 않았다

첫 시험기는 Python 모듈과 함수의 이름 충돌로 모델 호출 전에 멈췄다. 제품 source가 아닌
시험기 오류이고0모델 호출이었다. 자료를 보존하고 시험기만 수정했다.

다음 고정 시나리오에서는 실제2모델 호출 중 B는keep, A는review였다. A의 원문과
`ADMISSION_REVIEW` 상태를 보존했다. 이 시나리오는 **FAIL/미완료**이며 뒤의 수명주기
검증까지 도달하지 않았다. 전송·DB결함을 입증한 것도, 특정 문구가 원인임을 입증한 것도 아니다.

독립 방법 검토 후 별도 계획을 한 번 고정했다. 원래durable label의 **첫 두 ID001/002**를
확률과 무관하게 선택해 원문을 그대로 사용했다. 새 DB/bank, 실제Jev·공식TCP HTTP/엔진·
PostgreSQL/pgvector·E5로 실행했다. 기존2회와 합계4회 안에서만 모델을 호출했고, 추가
review가 나면 대조 입력을 바꾸지 않고 중단하도록 했다.

승인된 입력에서 다섯 계약이 통과했다: 원문 저장/검색, 지연 도착 시 입력 시각 보존,
API프로세스 재시작 후 read, API중단 때 접수한 입력의 뒤늦은 전송, 삭제 후 비노출.
28.064초·추가2모델 호출이었다. 이는 **승인된 입력의 기능적 수명주기**이며 새로운 독립
admission정확도 확인이나 최초A의 판단을 고친 증거가 아니다. 두 API세대와 앞선 실패의

## 경계20사례의 범위

실제 공식 ASGI HTTP handler, 내부Jev, PG/E5를 사용했다. 입력 대조군은 원래durable label의
첫6ID를 확률과 무관하게 정했다. 새 bank와 외부 scope bank, 명시 replacement·합성 secret·
주입 문자열을 호출 전에 고정했다. 모델 출력은 바꾸지 않고 관측만 했다.

- 출처5: 서로 다른5원문의 UTF-8원문·문서 식별자·연결 memory 확인.
- bank범위5: 다른 bank의 recall/get/delete/list와 외부 bank의 canary검색을 확인.
- 정정/삭제5: 삭제, 반복 삭제, 옛 사실 삭제, 새 사실 retain, 새 사실만 recall 확인.
- 입력 경계5: capture의 합성 secret거절, 서버가 실제Jev전송 전에 redaction, 악성 문장의
  비게시, 허용하지 않은document_id변경 및4KiB초과 입력의 사전 거절.

20개 실행 assertion이 통과했고9개 실제Jev응답이 있었다. 20개는 fixture를 공유하는 시나리오이며
독립적인20종 공격의 통계가 아니다. bank namespace는 다중 사용자 ACL이나 host의 프로젝트
자동 routing증거가 아니다. injection의503은 비게시를 증명하고 거절의 정확한 원인을
독립 확인한 것은 아니다. 정정은 **delete후새retain**이며 자동 모순 해결·원자적in-place수정이 아니다.
ASGI는 실제 handler/엔진을 호출하지만 kernelTCP transport는 별도 수명주기 시험의 범위다.

## 회사 호출은 미해결

설치된Codex CLI가 구독 로그인을 보고해도 실제 호출 성공은 아니었다. 제품의 동일한
isolationflags·기존 인증 경로에서120초에 응답하지 않았다. 한 번의 별도20초 진단도 시간
초과했고 connection-error범주만 확인됐다. **정확한 원인은 미확정**이다. raw계정/모델 로그는
저장·게시하지 않았으며 key문서·auth파일을 열거나 proxy/인증/네트워크 정책을 바꾸지 않았다.
`chatgpt.com`제외도 유지했다. 다른 provider로 대체하거나 forkedagent를 실제구독CLI증거로 세지 않았다.
CLI내부의 transport재시도 횟수는 미검증이다. 추가 무한 재시도는 하지 않았다.

## 아직100점이 아닌 이유와 다음 단계

독립 Sol이50개 개별결과와집계·source/질문해시·실제호출·실패보존·20사례·종료한프로세스를
확인했다. 현재 출시에 필요한 **QA100문항/프로필, 실제회사CLI, Mac입력/설치/성능, 최종1.0.0
배포물**은 이 결과로 대체할 수 없다. 실제 회사CLI/맥북의 실행 경로가 확보돼야 그 항목을
진행할 수 있다. 현재 연결된 실행 환경은 Linux뿐이며 사용자에게 두 정보를 요청한 상태다.
이 제약을 이유로 관련 없는 cloud튜닝을 늘리거나 출시 조건을 낮추지 않는다.

실제Jev호출은 합계64회다: 연결1+저장판단50+최초수명주기2+대조확인2+경계9.
이전 자료와 원문·정답·계정정보는 비공개로 보존하고, 공개 증거에는 집계와 해시만 담았다.
제품 source·모델/임계치·DB스키마는 바꾸지 않았고 새 모델 다운로드·CI·정식 tag/asset발행도 하지 않았다.
