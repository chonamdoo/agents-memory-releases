# C54: 실제 배포 전 클라우드 역할 대체 시험

2026-11-03(KST). 사용자가 아직 구성하지 않은 클라우드 서비스 역할을 현재 실행 환경의
loopback Hindsight API·컨테이너 PostgreSQL·로컬 E5로 대신했다. 개인 Jev는 실제 프로바이더를
호출했다. 소스는 c3 `30706fc…`, digest `c3cc2314…`로 고정했고 제품 코드는 바꾸지 않았다.
새 개선 후보 사용은 **2/3 그대로**다. GitHub CI는 실행하지 않았다.

이 시험은 Cloud Run 배포·외부 HTTPS·IAM·VPN·실제 원격 지연이나 Mac/Codex 설치를
대신하지 않는다. 회사 구독 CLI를 Jev나 테스트 대역으로 바꿔 통과 처리하지도 않았다.
회사 정책·평가 질문·정답은 외부 Jev에 보내지 않았다. 전송한 것은 고정된 합성 데이터다.

## 현재 소스에서 실제로 확인한 것

| 시험 | 결과 | 현재 점수에 반영하는 범위 |
| --- | --- | --- |
| 저장 판단 50사례 | durable keep 19/20, temporary discard 20/20, unsafe 보류 10/10. 50개 모두 실제 Jev 응답 완료 | 개인 저장 판단 10점 |
| 기본 수명주기 5항목 | 저장·검색, 입력 시각, 재시작 유지, 전송 장애·복구, 삭제 확인 | 개인 실제 통합 10점 |

저장 판단은 **과거 C51에서 사용한 고정 회귀 자료**다. 새 홀드아웃이나 최종 100문항 QA가
아니다. 이번 소스에서 새로 받은 첫 응답만 채점했고 실패한 durable 1개도 보존했다. 문장·
판단 기준·모델을 바꾸거나 실패한 모델 응답을 다시 뽑지 않았다.

실제 Jev 전송은 **63회**였다(판단 50 + 수명주기 4 + 안전 9). 실행 전 정한 전체 70회와
각 단계 상한 이내이며 클라이언트 재시도는 0이다. 안전 20개는 결합된 시나리오의 검증 항목이며
20개 독립 공격 유형을 뜻하지 않는다. bank 분리를 팀 사용자 ACL 보증으로 확대하지 않는다.
악성 지시에서 503을 관측한 경우는 비공개 저장 차단 증거이며 원인을 모두 입증한 것은 아니다.

## 최초 실패와 검증 코드 수정

기본 5항목은 통과했지만 최초 64 KiB 끝부분 검증에서 실패했다. 검증 코드가 엔진 내부의
`chunk_text`를 HTTP 응답에도 사용한 것이 원인이었다. 공식 HTTP `ChunkData`의 본문 필드는
`text`다. 최초 실패·원래 실행 파일·입력·해시를 보존하고, 검증 코드만 별도 v2 파일에서 고쳤다.

이미 저장한 원문을 그대로 읽어 이어갔으며 원문 capture/retain이나 그 모델 판단은 재시도하지
않았다. 질문과 검색 예산도 그대로다. 수정본을 위한 예정된 모델 호출 1회만 추가했다.
v2의 실제 HTTP 응답을 비공개로 저장해 원문/수정본 끝부분, 정정 후 옛 내용 부재, 세 번의
삭제·재시작 후 빈 결과를 독립 검토했다. 이것은 최종 QA 답변을 다시 생성한 실험이 아니다.
기록된 실행 시간 합계는 디버깅 사이 시간을 제외한 각 활성 시험 구간의 합이므로 전체 응답
시간이나 성능 점수로 사용하지 않는다.

## 삭제 절차의 한계

문서 ID 하나만 삭제하면 같은 입력의 다른 조각이 남는 것도 실제로 관측했다. 시험은 **전용
새 bank에서 공식 문서 목록 API로 전체 ID 목록을 확보하고 각 ID를 삭제하는 명시적 절차**다.
자동 그룹 ID 검색·원자적 일괄 수정·일반적인 공유 bank의 원문 묶음 탐색 기능을 추가하거나
검증한 것은 아니다. 운영에서는 처리한 전체 ID 목록을 관리해야 한다. 고정 사례의 통과를
아무 ID 하나만 삭제해도 전체 원문이 사라진다는 보증으로 해석하지 않는다.

## 입력 비차단 측정

제어된 로컬 HTTP 장애 응답을 기다리는 실제 worker lock이 100번 capture 동안 계속 유지됐다.
각 원문은 65,536바이트였고 100개 모두 새 프로세스에서 접수·원문 일치가 확인됐다.
p50 **88.12ms**, p95 **93.02ms**, 최대 **95.77ms**였다. 제어 게이트웨이 요청은 1개,
이 시험의 모델 호출은 0이다. 실제 Hindsight/모델의 처리 지연이나 Codex 호스트 이벤트 호출을
측정한 것은 아니며 Linux 수치를 Mac 성능 점수로 바꾸지 않았다.
집계는 실행 스크립트가 계산한 값이다. 이번에는 개별 시간 샘플 100개의 원자료를 저장하지
않아 독립 검토는 계산식·집계·원문 접수 상태를 확인했다. 정식 Mac 성능 검증에서는 개별
시간 샘플도 보존해야 한다.

## 점수와 남은 검증

현재 c3는 **개인 50 / 회사 15 / 공동 15점**이다. 과거 c1 receipt를 이전한 것이 아니라
이번 현재 소스의 실제 실행 receipt를 새로 연결했다. 동일 항목이 두 프로필에서 모두 통과해야
공동 점수를 얻으므로 정식 출시는 계속 차단된다.

고정 정책 100문항의 첫 답변·엄격 채점, 실제 회사 구독 CLI, Mac 설치·성능, 최종 배포물은
미검증이다. 회사도 Mac + Codex라는 대상 설정은 확정됐고 실제 실행은 앞선 사용자 지시대로
뒤로 미뤘다. 이를 대신하는 가짜 통과 점수는 주지 않는다. SOTA 또는 실제 클라우드 배포
완료를 주장하지 않으며 100/100 이전에는 정식 tag·release·asset을 게시하지 않는다.
