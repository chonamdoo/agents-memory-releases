# C52: 회사 대상 확정과 긴 문서 검증 준비

2026-11-03(KST). 이 문서는 C52 당시의 이력을 보존한다. 현재 권장 후보와 점수는
[C3 기록](VERIFICATION-C53-20261103.ko.md)과 점수표를 따른다(새 후보 2/3 사용).
회사도 **Mac + Codex**라는 사용자 확인을 반영했다. 회사의 구독 저장 판단과
답변·judge 모델은 Sol 대상 설정이다. 실제 회사 CLI 연결과 Mac 검증은 사용자 지시에 따라
뒤로 미뤘다. 설정이 정해졌다는 이유로 실제 실행·Mac 설치 점수를 주지 않는다.

## 확인한 입력 제한과 후속 후보

C52 당시 점수표의 c1은 작은 문서를 대상으로 확인한 기준 후보였다. 사용자 제공 정책 87개를
c1 저장 판단 요청 생성기에 넣으면 4 KiB 한도 때문에 20개만 허용되고 67개는 거절된다.
원본은 총 873,813바이트, 최대 47,888바이트다. 이는 입력 허용 여부이며 저장 판단 정답률이 아니다.

후속 c2는 원문 한 개와 요청 전체를 각각 최대 64 KiB, 한 번에 최대 16개로 맞춘다. 기억할
확률 기준과 악성 지시 기준은 그대로 유지하고, 원문을 자르거나 과거 review 항목을 자동
전송하지 않는다. 방어 처리 후 커진 입력도 판단 요청 직전에 다시 검사한다.

- 실제 Jev에 **합성 데이터만** 보낸 사전 용량 확인: 48 KiB 한 개, 64 KiB 한 개,
  16 × 4 KiB 요청의 typed 응답을 각각 한 번 확인했다. 긴 문서 이해도나 최종 QA 증거는 아니다.
- c2의 요청 생성기는 87개 모두를 원본 바이트와 동일하게 허용했다. 모델의 승인·실제 저장
  성공을 뜻하지 않는다. 회사 정책 원문을 개인 Jev로 전송하지 않았다.
- 관련 로컬 엄격 회귀 256개 및 모든 setup/call/teardown 통과, 실패·skip·xfail·xpass 0.
  새 patch의 독립 복사 적용과 원래 설치된 공식 패키지 불변을 확인했다.
- 미출시 1.0.0 wheel을 오프라인으로 빌드하고 별도 Linux 환경에서 선택 의존성 없이
  64 KiB capture 원문 일치를 확인했다. 단일 측정 약 96ms이며 Mac p95 또는 완전 설치
  검증으로 인정하지 않는다. wheel은 정식 asset으로 업로드하지 않았다.

당시 새 개선 후보는 **1/3 사용**이었다. c2 소스·patch의 증거를 c1 receipt에 덮어쓰거나, 이전 실제
프로바이더 검증을 새 소스에서 실행한 것처럼 재결합하지 않는다. c1의 기존 점수는 c1에만 해당한다.

실제 c2 훅→HTTP→Jev→PostgreSQL/E5 경로에서 48 KiB 합성 원문이 승인되고 queue/wire/DB/
문서 조회 원문 해시 및 끝부분 회상까지 일치했다. 이어진 64 KiB도 모델 `keep`·HTTP 200을
받았지만 문서가 한 개라는 검증 조건이 실패했다. 읽기 전용 진단에서 서로 다른 두 문서의
원문이 각각 전체 65,536바이트·원본 SHA와 일치했고 청크가 21+2개로 분산돼 있었다.
공식 upstream은 10,000토큰 배치 경계를 넘으면 자동 문서 ID를 부분별로 할당하는 동작을
문서화한다. 원문 절단은 없었지만, 이 실행을 64 KiB 전체 수명주기 통과로 바꾸지 않는다.
64 KiB 문서 조회·회상 API 검증과 묶음 수정·삭제는 미완료다. 최초 실패·입력·결과를 보존했고
재시도하지 않았다. 실제 모델 호출은 2회, 세 번째 마스킹 사례는 실행되지 않았다.

독립 리뷰 중 기존 훅의 패턴 검사에 Hindsight 자체 키 형식이 빠진 점을 발견했다. 공식 서버의
MemoryDefense는 이 형식을 가리지만, 그 이전 로컬 큐 검사는 같은 패턴을 인식하지 않는다. 실제 설치된 c2 wheel의 합성 키 capture에서
`queued`와 로컬 원문 존재를 재현했다. 해당 입력은 drain하지 않았고 외부·모델 호출은 0이다.
c1과 c2의 검사 모듈 바이트가 동일하므로 현재 c1 안전 배점도 철회했다(개인 35 / 회사 15 / 공동 15).
[철회 기록](evidence/security-withdrawal-c52.json)은 원래 C51 20사례 통과 기록을 보존한다.
합성 키의 서버 전송 전 마스킹과 훅의 저장 전 차단은 별개다. 이것을 비밀정보 차단 통과나
보편적인 DLP 보증으로 세지 않는다. 고정한 c2 증거를 바꾸지 않고 별도 후속 후보에서 입력·drain
경계를 수정·재검증해야 하며, 그 전에는 정식 버전의 비밀정보 처리 완료를 주장하지 않는다.
그 후속 검증은 [C3 기록](VERIFICATION-C53-20261103.ko.md)에서 따로 관리한다.

## 100문항 준비와 공식 대조군

사내 정책으로 답 가능 80개·자연스러운 답 없음 20개의 고정 평가 세트를 만들었다.
47개 문서와 정확한 원문 인용 135개를 확인했으며 15개는 여러 문서를 근거로 작성했다. 질문·정답은
분리 보관하고, reader에게는 정답 가능 여부를 제거한 id·질문만 전달하도록 순서를 미리 고정했다.
질문·정답·회사 원문은 공개 저장소에 올리지 않는다.

작성자는 과거 같은 자료의 평가에 관여했으므로 완전히 새로운 코퍼스나 과거 결과를 전혀 모르는
블라인드 작성이라고 주장하지 않는다. Sol 독립 사전 검토에서 100문항의 정답·루브릭·근거 및
답 없음 20개에 차단할 문제를 발견하지 않았다. 채점은 물은 사실만 요구하며 동등한 표현과
유효한 다른 근거를 허용한다. 실제 평가에서는 첫 답변만 고정해
채점해야 한다. 이전 소규모 QA 결과를 이 100문항의 결과로 바꾸지 않는다.

공식 Hindsight 원본 패키지의 None/chunks, 3,000자 청크, 로컬 E5-small, RRF 구성에 원문
87개를 적재했다. 문서 87개·청크 237개·기억 단위 237개를 확인했고 원문 873,813바이트가
저장 원문과 일치했다. 외부 생성형 API 호출은 0이며 DB는 적재 후 읽기 전용으로 고정했다.
적재는 약 37.1초였다. 이는 대조군 준비 시간이며 검색·최종 답변 지연 측정이 아니다.

**100문항 첫 답변과 실제 회사 프로바이더 비교는 아직 실행하지 않았다.** QA 35점·Mac 검증·
정식 배포물 점수는 보류다. 기준을 완화하거나 Linux 증거를 Mac 통과로 바꾸지 않는다.
