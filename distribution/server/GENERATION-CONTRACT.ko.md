# MCP 2.0.5 판단·원문 보존·검색 계약 (런타임 ABI 2.0.0)

v2.0.4의 Jev 독립 품질·앱 수명주기 결과와 과거 실패 기록은 그대로 보존한다.
이번 릴리즈의 새 검증은 로컬 공급자 선택·전송·격리·설치 기능이다. 로컬 모델이나
구독 모델에 v2.0.4의 Jev 품질 수치를 적용하지 않는다. 실제 로컬 모델 품질은 미측정이다.

로컬 설치는 `jev` 또는 `local`을 선택한다. `local --local-host openai`는
Ollama·LM Studio의 loopback HTTP `/v1` 구조화 출력이다. `--local-host claude|codex`는
로그인된 CLI 구독 경로이고 추론은 업체 서버에서 실행된다. 구독 CLI는 도구·MCP·규칙·
세션 저장을 비활성화하며 API 키·우회 경로 설정을 발견하면 거절한다. CLI 실패를 API 과금으로
대체하지 않는다. 서버 모드는 Jev만 허용한다. 로컬 모델의 판단 점수는 자체 보고 점수이며
Jev의 보정 확률과 동등하다고 해석하지 않는다. 애매한 판단은 기존 검토 보류 정책을 따른다.

원문은 선택한 공급자에 전달된다. Jev 키는 비공개 파일·숨김 입력만 사용하고,
로컬 경로에서는 Jev 키를 읽지 않는다. 기존 DB·키·선택 모델을 보존하고 명시적 전환만 허용한다.
실패한 공급자를 다른 공급자로 대체하지 않는다. 같은 공급자 업데이트 실패 시 이전 설치를 복원한다.

기본 `integrated` 경로는 `SourceIntegrator`를 사용한다.
통합을 위해 별도 모델 판정을 하지 않는다. 원문 전체가 정확히 같은 사실만
출처를 합치며, 비슷한 내용·부정·조건·시점이 다른 사실은 별도로 보존한다.
의미가 비슷하다는 이유로 재서술하거나 최신값을 선택하지 않는다.
상태는 `generation_enabled=false`, `integration_enabled=true`다.
명시적 `generative` 재서술은 지원하지 않으며 빠르게 거절한다.

처리 완료는 공급자 실행 또는 접수 응답이 아니다. Hindsight의 문서
본문·귀속을 읽어 확인하고, 추출된 fact가 존재하며, 통합 작업이 completed인
경우에만 현재 revision·변경 로그를 공개한다. 변경 공개 뒤 과거 문서를
정리하고 살아 있는 출처로 다시 통합한 후 완료를 응답한다. 삭제는 권한을
확인한 SQL tombstone을 먼저 공개한 뒤 외부 문서를 정리한다.
공급자 실패는 원래 작업 ID·원문 의도·준비 결과를 보존한다. 기존 폐기·실패를
새 작업으로 재등록하지 않으며 검토 보류를 자동 재과금 재시도하지 않는다.

관찰 통합은 기존 게이트웨이의 내부 transport와 `SourceIntegrator`에서
실행한다. 추가 판단 서버·별도 생성 모델·OAuth 복사는 없다.
내부 transport는 시작마다 새 비공개 nonce와 실제 loopback peer가 필요하며
일반 계정 키로 호출할 수 없다. 과거 구독 CLI 호출 상한·격리 실험의 증거를
현재 선택한 공급자의 독립 품질 검증으로 재사용하지 않는다.

생성된 observation은 출처 fact가 모두 확인돼야 검색 후보가 된다. 그 모든 출처가
현재 revision·삭제 상태·사용자·프로젝트·팀 공유 권한을 만족하는지 최종 SQL에서
다시 확인한다. 일부 출처가 누락되거나 검색 응답의 provenance 예산이 잘렸다면
그 observation을 반환하지 않는다. 최종 순위 점수를 의미 일치 확률로 쓰지 않는다.
개발 자료에 맞춘 native cosine 바닥값은 다국어 회상 회귀가 확인되어
적용하지 않는다. 회상률·잡음은 독립 평가로 별도 확인해야 한다.

이어가기 brief는 일반 검색 문구로 관찰을 검색하지 않는다. 현재 권한·revision을
통과한 최근 후보의 본문을 Native에서 읽어 canonical text와 정확히 같은 경우에만
사용한다. SQL 본문만으로 회상을 대신하지 않는다. 사실을 중간에서 자르지 않으며,
전체 길이 예산에 맞지 않는 사실은 통째로 제외한다. 따라서 뒤쪽 부정·예외를
잘라 의미를 바꾸지 않는다.

호스트 훅도 원문 전체만 전달한다. 검색 후보 5개 안에서 notice·JSON 포장을 포함한
4096 UTF-8 byte 예산을 적용한다. MCP 시작 문맥은 최대 10개 기억의 canonical
배열을 대괄호·escaping·구분자까지 6000 UTF-8 byte 안에서 선택한다.
개별 기억을 500자·1000자로 잘라 넣지 않는다. 남은 예산에 맞지 않는 기억은 통째로
건너뛰고 뒤의 후보를 검토하므로, 마지막 부정·예외가 빠진 일부 원문을 사실로 전달하지 않는다.
omp adapter는 stdout 청크마다 따로 문자열로 바꾸지 않고 스트림 UTF-8 decoder를
사용한다. 청크 경계가 문자 중간에 와도 원문을 보존하며, 8192-byte 출력 한도와
4096-byte 문맥 한도는 그대로 적용한다.

현재 검색은 고정 multilingual E5와 RRF 후보 결합 뒤 필수 다국어 ONNX
cross-encoder로 재순위를 매긴다. E5/RRF 점수를 그대로 통과시키는 경로가 아니다.
모델은 `BAAI/bge-reranker-v2-m3`,
revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`로 고정한다.
정확한 6개 파일과 tokenizer 해시는 `reranker-assets.sha256.json`을 따른다.
준비된 모델 디렉터리는 최초 엔진 설치의 필수 자산이며 원격 연결 클라이언트에는 필요 없다.
모델을 자동 다운로드하지 않으며 출처·라이선스는 모델 디렉터리 밖에 둔다.

원본 `model.safetensors` SHA-256은
`d9e3e081faff1eefb84019509b2f5558fd74c1a05a2c7db22f74174fcedb5286`이고,
FP16 가중치·eager encoder·FP32 Sigmoid 출력으로 내보낸 런타임 그래프 SHA-256은
`cfc1a4de75f13cd68467b84bddbe2f9b87033782e9bbef43f7f85292758c0af1`다.
원본 텐서 393개가 단일 그래프에 포함되며 외부 런타임 텐서는 없다.
FP32와 FP16 기준 모델의 6쌍 최대 절대 오차는 `0.00022161006927490234`다.
ONNX와 같은 정밀도의 기준 모델 간 수치 일치는 아직 측정하지 않았으며,
이 수치나 파일 해시는 검색 품질 증거가 아니다.
Sigmoid 점수는 보편적으로 보정된 관련성 확률이 아니다. 공유 SDK 회상 경계의
native `min_scores.reranker=0.003`은 사전 고정한 새 개발 세트에서만 선택한 경험적 기준이다.
SQL cosine cutoff가 아니며 과거 전역 E5 `0.84` 기준은 거부되어 적용하지 않는다.
독립 출시 품질 검증이나 모든 언어의 무관 기억 제외를 입증하지 않는다.
모델 이름이나 다국어 표기만으로 한국어 검색 품질을 보장하지 않는다.

CPU 실행은 batch 1, threads 2, `max_tokens=512`다.
native reranker timeout은 `0`으로 두어 시간 초과 뒤 미채점 후보를 반환하는
fallback을 피한다. 외부 HTTP timeout은 서버 추론의 취소·종료를 입증하지 않는다.

SQL/SQLite의 canonical text는 승인된 근거 구간이다. 온라인 회상은 Hindsight의
관찰과 현재 출처를 사용하고, 오프라인 개인 캐시는 이미 받은 근거를
stale로 표시한다. 팀 문맥을 권한 오류 뒤 캐시에서 되살리지 않는다.

초기 `MEMORY-CONTRACT.md`는 근거 구간 선택 슬라이스의 기록이다.
현재 기본 경로는 원문 보존 통합이며, wire 식별자·작업 fingerprint와 기존
canonical 데이터는 보존한다. 기존 사용자 데이터를 자동 재분류하거나 삭제하지 않는다.

수정 중 공급자 장애가 나면 이전 SQL revision과 원문 의도는 보존되지만,
외부 색인 변경과 SQL 공개가 하나의 분산 트랜잭션은 아니다. 과거 문서 제거 후
통합 재시도가 끝날 때까지 검색 가용성이 줄 수 있다. 재시도 후의 수렴을
검증하며, 장애 중에도 모든 검색이 항상 이전 결과를 반환한다는 보장은 하지 않는다.

릴리즈 후보의 패키지 설치·업데이트·실제 앱 검증 결과와 미검증 플랫폼은 릴리즈 보고서에 별도로 기록한다. 기존 1.0.7 코어와
0.2.1 서버 이미지는 이 생성형 제품 경로를 포함하지 않는다.
