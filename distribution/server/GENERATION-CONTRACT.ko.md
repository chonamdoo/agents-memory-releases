# 공급자 세 가지와 제품의 생성형 처리

지원 공급자는 `claude`, `codex`, `jev`다. Claude/Codex는 기억 엔진을 실행하는
호스트에서 직접 구독 로그인한 CLI다. 별도 가중치 모델 설치·다운로드는 제품
범위에 없다. OMP는 Claude·Codex와 함께 MCP 연결 대상이며 판단 공급자 선택과
별개다. 설치 위치(local/personal-server/team-server/company-server)는 공급자나
기억 처리 알고리즘을 바꾸지 않는다.

| 선택 | 실제 처리 | 외부 전송 |
|---|---|---|
| Claude CLI | 저장 판단·근거 선택 → Hindsight 생성형 추출·통합 → 출처를 검증한 회상 | 선택한 CLI의 구독 서비스 |
| Codex CLI | 같은 단계, 선택한 Codex CLI만 사용 | 선택한 CLI의 구독 서비스 |
| Jev | typed 저장 판단·원문 근거 선택 → 같은 주제의 호환 사실 판단·원문 보존 통합 → Hindsight 회상 | 선택한 Jev API |

현재 연결한 Jev System One API는 자유 생성형 응답 계약을 제공하지 않는다.
Jev를 선택했을 때 다른 공급자를 자동 호출하지 않는다. 상태에
`generation_enabled=false`, `integration_enabled=true`를 표시한다. 같은 대상·속성의 호환되는 사실을 typed 확률로 판단하고, 인용 원문을 모두 유지한 관찰로 연결한다. 상충·시점 변경·불확실한 사실은 따로 보존하며 자의적인 최신값 선택이나 자유 재서술을 하지 않는다. 임계값만으로 의미 정확성을 증명하지 않으며 실호출 합성 사례와 제어 흐름 검증을 구분한다.
세 공급자의 기능 차이와 네 설치 위치의 기능 차이를 혼동하지 않는다.

세 공급자 선택의 처리 완료는 모델 실행 또는 접수 응답이 아니다. Hindsight의 문서
본문·귀속을 읽어 확인하고, 추출된 fact가 존재하며, 통합 작업이 completed인
경우에만 현재 revision·변경 로그를 공개한다. 수정으로 과거 문서를 제거하면
그 출처를 인용한 관찰도 무효화될 수 있으므로 살아 있는 출처로 다시 통합한 뒤
새 revision을 공개한다. 공급자 실패는 미전송 의도와 준비 결과를 남겨 재시도한다.

외부 통합 호출은 기존 게이트웨이의 내부 transport와 선택한 CLI 또는 Jev typed 어댑터를 사용한다.
추가 서버·별도 생성 모델·OAuth 복사는 없다. 세션/프로젝트 지침·도구가 없는
분리된 실행 디렉터리에서 처리한다. 내부 transport는 시작마다 새로 발급한 비공개
nonce와 실제 loopback peer가 필요하며 일반 계정 키로 호출할 수 없다.

생성된 observation은 출처 fact가 모두 확인돼야 검색 후보가 된다. 그 모든 출처가
현재 revision·삭제 상태·사용자·프로젝트·팀 공유 권한을 만족하는지 최종 SQL에서
다시 확인한다. 일부 출처가 누락되거나 검색 응답의 provenance 예산이 잘렸다면
그 observation을 반환하지 않는다. 검색 품질과 완전성은 별도 검증 대상이다.

SQL/SQLite의 canonical text는 승인된 근거 구간이다. 온라인 회상은 Hindsight의
생성된 지식과 현재 출처를 사용하고, 오프라인 개인 캐시는 이미 받은 근거를
stale로 표시한다. 모든 기억의 재서술 문자열이 기기 캐시에 동일하게 복제된다고
주장하지 않는다. 팀 문맥을 권한 오류 뒤 캐시에서 되살리지 않는다.

초기 `MEMORY-CONTRACT.md`는 생성형 기능을 포함하지 않았던 근거 구간 선택
슬라이스의 기록이다. 이 문서는 그 단계에 CLI 생성형 처리를 연결한 범위와
제한을 명시한다. wire 계약의 식별자/작업 fingerprint와 기존 canonical 데이터는
보존한다. 기존 사용자 데이터를 자동 재분류하거나 삭제하지 않는다.

수정 중 공급자 장애가 나면 이전 SQL revision과 원문 의도는 보존되지만,
외부 색인 변경과 SQL 공개가 하나의 분산 트랜잭션은 아니다. 과거 문서 제거 후
통합 재시도가 끝날 때까지 검색 가용성이 줄 수 있다. 재시도 후의 수렴을
검증하며, 장애 중에도 모든 검색이 항상 이전 결과를 반환한다는 보장은 하지 않는다.

릴리즈 후보의 패키지 설치·업데이트·실제 앱 검증 결과와 미검증 플랫폼은 릴리즈 보고서에 별도로 기록한다. 기존 1.0.7 코어와
0.2.1 서버 이미지는 이 생성형 제품 경로를 포함하지 않는다.
